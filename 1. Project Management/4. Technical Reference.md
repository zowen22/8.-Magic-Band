## Enclosure Notes

- Ornament shell: 3D printed
- Barrel jack: 5.5mm/2.1mm panel-mount, requires **11mm hole** in shell
- Orient jack on bottom — cable exits downward, follows ornament wire naturally
- Minimum 15mm clearance behind jack inside shell for solder tabs + wiring
- Nano footprint: 18mm × 45mm — plan mounting accordingly

## RF Workflow (per unit)

1. Run `Sniffer.ino` with receiver on pin 2 — press all remote buttons, record codes
2. Fill `RF_CODE_ON`, `RF_CODE_OFF`, `RF_BITS`, `RF_PROTOCOL` in Rev4
3. Flash Rev4, put outlet in learn mode, scan any RFID card to pair
4. Confirm outlet responds, ship pre-paired

## Known Constraints / Gotchas

- Nano VIN accepts 7–12V regulated but 5V works fine from a regulated supply
- MFRC522 is 3.3V — use Nano's 3V3 pin, not 5V
- DFPlayer audio file must be named `001.mp3` on the SD card root
- rc-switch `send()` is blocking — NeoPixel animations must complete before RF fires
- 433MHz is fire-and-forget (no ACK) — send code 5× to ensure reception (`RF_REPEAT`)
- Nano has Mini-USB for programming; power in production via VIN barrel jack

## Dev Environment: Arduino USB Access from WSL2

Dev machine is Windows + WSL2 (Ubuntu). The board connects via USB to Windows and is
**not** visible in WSL by default — needs a bridge. Worked out 2026-08-03; steps below
to redo it (new machine, reboot, board reconnected, etc.).

### One-time setup

**Windows (Admin PowerShell):**
```powershell
winget install usbipd
```

**WSL (regular interactive terminal — needs real sudo, see caveat below):**
```bash
sudo apt-get update
sudo apt-get install -y linux-tools-generic hwdata
sudo update-alternatives --install /usr/local/bin/usbip usbip /usr/lib/linux-tools/*-generic/usbip 20
sudo usermod -aG dialout $USER
```
After `usermod`, open a **new** terminal window — group membership doesn't apply
retroactively to the shell you ran it from (`newgrp dialout` also works if `newgrp`
happens to be installed; wasn't on this machine's minimal Ubuntu image).

### Per-connect (every time the board is plugged in, or after a reboot)

**Windows (Admin PowerShell):**
```powershell
usbipd list                    # find the board's BUSID
usbipd bind --busid <BUSID>    # one-time per device, not per session
usbipd attach --wsl --busid <BUSID>
```
Our board enumerates as CH340, VID:PID `1a86:7523`. Keep that PowerShell window open —
the attach only holds while it's running (or use `usbipd attach -a` for auto-reattach).

**WSL:**
```bash
arduino-cli board list   # should show /dev/ttyUSB0 once attached
```

### Dead ends — don't retry these

- **Mapping `\\wsl$\...` as a network drive** (`net use`, `New-PSDrive -Persist`,
  Explorer's "Map Network Drive" wizard) — all fail with "network name no longer
  available," or loop on a credential prompt that goes nowhere. The share works fine for
  *browsing* in Explorer or passing a raw UNC path as a CLI argument — just not for
  persistent drive mapping.
- **Opening sketches in Arduino IDE via a `\\wsl$\...` path** — the IDE's file-open
  dialog silently creates a blank `sketch_xxxx` instead of loading the real file, even
  when the dialog itself accepted the path. Legacy Windows file APIs mishandling UNC
  paths, not a content problem. Drag-and-drop from an open Explorer window onto the IDE
  window works around it; better to just skip the IDE GUI (see below).
- **Doing any of this from a Claude Code background job** — those run in a locked-down
  container with its own synthetic `/dev` that doesn't include real hardware, even after
  a successful `usbipd attach`. The kernel genuinely does bind the board (visible in the
  WSL2 VM's own `dmesg`), but the job's container can't see it, and there's no
  permission or sudo that changes that — it's a mount-namespace boundary, not an access
  grant. Needs a real interactive WSL terminal.

### Recommended workflow

Skip Windows/Arduino IDE entirely for compiling and flashing. Work from a plain
interactive WSL terminal, straight against the repo — no UNC paths, no drive mapping:
```bash
cd ~/projects/8.-Magic-Band/<sketch-folder>
arduino-cli compile --fqbn <fqbn> .
arduino-cli upload -p /dev/ttyUSB0 --fqbn <fqbn> .
arduino-cli monitor -p /dev/ttyUSB0 -c baudrate=9600
```
`arduino-cli`, the `arduino:avr` core, and all required libraries (MFRC522, Adafruit
NeoPixel, rc-switch, DFRobotDFPlayerMini) are already installed under this WSL user
account.
