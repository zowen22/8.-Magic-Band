# Project Overview

*Generated from Problem Statement: 2026-06-16*

-----

## Summary

A Christmas tree ornament with an embedded MFRC522 RFID reader and two NeoPixel rings. Tapping a Disney MagicBand (or any RFID card) triggers a light animation and toggles a relay in a floor-level power box that switches 120V mains to the tree lights. The ornament and power box are connected by a discrete hidden wire.

## Scope

### In:
- Arduino firmware (RFID detection, NeoPixel animations, relay control)
- Code cleanup and bug fixes on existing sketch
- Optional: UID whitelist to restrict access to specific bands
- Optional: DFPlayer Mini audio cue (currently disabled due to pin conflict)
- Hardware documentation (pin map, wiring, BOM)

### Out:
- Enclosure design / 3D printing (separate effort)
- PCB design
- Network/wireless integration

## Decisions Log

| Date | Decision | Rationale |
|---|---|---|
| 2026-06-16 | Start clean rewrite in new file (Rev3) rather than patching Rev2 | Multiple structural issues; cleaner to rewrite than layer fixes on messy code |
| 2026-06-16 | Use `TreeOn` boolean (already declared, never used) instead of counter parity | More readable, intent is clear, eliminates counter-starts-at-2 confusion |
| 2026-06-16 | DFPlayer re-integrated — moved to pins 2/3, RFID SS to pin 4 | Eliminates pin 10 conflict cleanly |
| 2026-06-16 | Replace relay + floor box with 433MHz RF outlet | No mains wiring on product side; outlet is UL-listed; no buyer setup required (pre-paired before shipping) |
| 2026-06-16 | Arduino Nano instead of Uno | Smaller footprint for ornament; identical pin numbers, zero code changes |
| 2026-06-16 | 5.5mm/2.1mm barrel jack on ornament shell | Clean panel-mount interface; standard commodity supply; no floor box needed |
| 2026-08-04 | Add external MCP1700-3302 regulator to wireless variant (corrected from an initial AMS1117 choice same day) | Pro Mini has only one onboard regulator (5V) — no separate 3.3V pin for MFRC522/RF TX module. AMS1117's ~mA-range quiescent current would have dominated the sleep budget; MCP1700's 1.6uA doesn't. |
| 2026-08-04 | Custom PCB: KiCad + carrier/breakout approach (not fully custom/integrated) | User is new to PCB design and prototype lead times are costly if wrong — carrier board keeps Pro Mini/MFRC522/NeoPixels/RF TX as pluggable off-the-shelf modules, so a design mistake costs a cheap module respin, not a full board respin |
| 2026-08-04 | Integrate MOSFET switch circuit directly onto v2 board (Q1/R2/R3), replacing the external Adafruit MOSFET driver module | Basic, well-understood circuit (unlike RFID/RF, which stay external) -- removes a module + connector from the BOM at low risk |
| 2026-08-04 | Pause battery-powered wireless variant, pivot back to barrel-jack/wall-powered architecture | LiPo batteries carry real shipping/hazmat friction (UN38.3, carrier rules) and marketplace listing restrictions (Etsy) if this becomes a sellable product -- avoiding that class of problem outweighs the battery variant's untethering benefit. RFID/RF/NeoPixel work carries forward; battery-specific power-management complexity (sleep/wake, MOSFET gating for battery life, low-quiescent regulator) is no longer required on wall power. |
