## 2026-07-12 - Wireless Variant: Power Architecture, Audit, Pricing

*Status: `COMPLETED`*
*Type: `Manual`*

### What Was Done
- Worked through PowerBoost 1000C stock-out: evaluated Seeed Lipo Rider Plus, SparkFun LiPo Charger/Booster, Adafruit PowerBoost 500C, DFRobot MP2636 — selected Lipo Rider Plus (USB-C, 2.4A headroom, in stock)
- Confirmed none of the recommended boost/charge boards have "smart power bank" auto-shutoff-at-low-load behavior (that's specific to phone-charging power bank ICs); confirmed over-discharge protection comes from the battery's own protection PCB, not the booster
- Corrected earlier "many days" runtime claim: continuous RFID scanning draws ~20hrs on a 2000mAh cell, not multi-day
- Modeled 1Hz duty-cycle polling: naive version (RFID gated, nothing else) barely helps, because Nano's onboard CH340 chip (5–20mA idle, doesn't sleep) and NeoPixels' off-state driver current (~0.6mA/pixel, confirmed via bench measurement + datasheet) dominate. Recommended swapping Nano → Pro Mini (drops CH340 floor) and MOSFET-gating NeoPixel (and previously DFPlayer) power
- Ran a mini audit on all consumption figures used this session, with sources and confidence levels; one unresolved gap — boost converter no-load quiescent current, needs bench test
- Priced the full BOM (parts + consumption per component)
- Dropped audio (DFPlayer + speaker + microSD) from the wireless variant's baseline BOM per user direction — kept optional in both the wired and wireless docs, consistent with existing Problem Statement scope, not fully removed
- Rewrote `BOM - Wireless Ornament Variant.md` to reflect all of the above: Pro Mini, Lipo Rider Plus, MOSFET gating, audio-as-optional, sourced power budget with two runtime scenarios, updated pricing
- Merged the branch to `main` per user request — working on `main` going forward, not the feature branch

### Decisions Made
- Lipo Rider Plus over PowerBoost 1000C (stock-driven, but also higher current headroom)
- Pro Mini over Nano for the wireless variant specifically — needed to hit meaningful battery runtime; wired-build Technical Reference still specifies Nano, unchanged
- Audio stays optional in both builds, not stripped from either — user's explicit call after I flagged the scope question
- Runtime estimates now split into "properly engineered" (~2-4 weeks) vs. "unoptimized fallback" (~18-20hrs) rather than a single number, since the gap is entirely firmware sleep/wake + MOSFET gating, not battery size

### Blockers / Issues
- Boost converter no-load quiescent current still unverified — could not extract a figure from TI's datasheet via search. Flagged in BOM doc; needs a bench measurement before the multi-week runtime estimate is trustworthy.
- Pro Mini active-current figure used (~15-20mA) is a general datasheet estimate, not independently re-verified this session

### Next Session
- Bench-test: Lipo Rider Plus no-load current, actual Pro Mini active current
- Write firmware: Pro Mini sleep/wake loop (~1Hz RFID poll) + MOSFET-gated NeoPixel power
- Check Lipo Rider Plus + battery physical dimensions against shell interior once WP2.2 progresses
