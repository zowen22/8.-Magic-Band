*Status: `COMPLETED`*
*Type: `Manual`*

### What Was Done
- Ran an independent review pass on `PCB/MagicBand_Carrier/MagicBand_Carrier.kicad_sch` -- a different agent than the one that built it, checking against real datasheets/reference material rather than just internal consistency, per the user's ask for the most thorough process available before locking anything in
- Confirmed correct (verified against real sources, not just re-reading the schematic): MOSFET driver low-side-switching topology (matches Adafruit's own PID 5648 docs -- V+ passthrough, switched ground return), MFRC522 pin wiring (matches a real RC522 breakout's pin order and `MagicBand_Wireless.ino`'s documented map exactly), power/ground net separation (exported and inspected the actual netlist -- GND and GND_SW share zero nodes, no crossed rails, only J2 pin 5/IRQ is unconnected and that's intentional)
- Found one real problem: MCP1700-3302's decoupling caps (C1 input, C2 output) were both 100nF. - Fixed: C2 (output) -> 1.0uF per datasheet; C1 (input) -> 10uF, typical reference-design sizing for this part (not itself a stability requirement, but standard practice for transient headroom on the input side)
- Re-ran ERC after the fix: still 0 errors, same 120 cosmetic warnings (grid-alignment + missing lib-table config, unchanged from before) -- confirms the value change didn't introduce anything new
- Re-exported `schematic.pdf`
- Checked whether `PCB/MagicBand_FullyCustom/` (v2, bare ATmega328P) existed yet to apply the same fix there -- it didn't exist at the time of this fix, so v2 still needs the identical C1/C2 correction applied once its schematic lands

### Decisions Made
- Independent review (separate from whoever builds a given schematic revision) is now the standard step before moving any board revision to layout -- caught a real, datasheet-verifiable problem the builder's own ERC pass couldn't catch, since ERC checks connectivity rules, not component value correctness against a part's actual datasheet

## 2026-08-04 - V1 Carrier-Board Schematic: Built and ERC-Clean

*Status: `COMPLETED`*
*Type: `Manual`*

### What Was Done
- Built the actual KiCad v1 carrier-board schematic (`PCB/MagicBand_Carrier/MagicBand_Carrier.kicad_sch` + `.kicad_pro`) -- real file creation via kicad-cli, not GUI clicks, per the user's explicit "you do it" direction
- All components from the PCB Design Plan present and wired per `MagicBand_Wireless.ino`'s pin map: J1 Pro Mini (11 used pins), J2 MFRC522 (8 pins, IRQ correctly left no-connect), J3 RF TX module, J4/J5 MOSFET driver in/out, J6/J7 NeoPixel outer/inner headers, J8 5V power input, U1 MCP1700-3302 with C1/C2 100nF decoupling caps
- **ERC-clean: 0 errors.** Took real debugging to get there -- three distinct bugs found and fixed along the way, all worth remembering for next time (full detail in commit `TBD`):
  1. Embedded library symbols must be renamed to `"LibraryNickname:SymbolName"` to match the `lib_id` instances reference -- otherwise KiCad silently fails to resolve pin geometry (defaults every pin to the symbol's placement origin) with no obvious error pointing at the real cause
  2. Even-numbered `Conn_01xNN` connectors do NOT use the same symmetric pin-spacing formula as odd-numbered ones (confirmed by reading the actual library files, not assuming) -- N=2's pin 1 is at local y=0, not the guessed +1.27
  3. **Library symbol coordinate space is Y-up; schematic sheet space is Y-down** -- a pin's real absolute Y is `sheet_y - local_y`, not `sheet_y + local_y`. This one silently broke every non-zero-Y pin across the whole file and took the longest to isolate (confirmed via an isolated single-connector test case, not by guessing against the full 94-item file)
- Remaining 120 ERC items are all warnings, all benign: grid-alignment cosmetics (`endpoint_off_grid`, from arbitrary placement coordinates not snapped to KiCad's default grid) and missing project-level sym-lib-table/fp-lib-table config (cosmetic for future GUI editing -- every symbol used is already fully embedded in the schematic file itself, so this doesn't affect validity)
- Added `power:PWR_FLAG` on the 5V and GND nets at J8 (the board's power input) -- textbook fix for "no driver on this net," since 5V/GND legitimately originate off-board from the external Lipo Rider Plus, not from anything visible in this schematic
- Exported `schematic.pdf` for visual review (rendered and visually confirmed net-by-net against the pin map)

### Decisions Made
- None beyond what the PCB Design Plan already specified -- this session executed that plan, didn't revise it

### Blockers / Issues
