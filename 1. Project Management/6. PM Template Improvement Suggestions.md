## 2026-08-07 - Dashboard "next steps" heuristic is unreliable, and its doc is out of sync with its code

*Status: `Proposed`*

**Observation:**

CLAUDE.md's "Project Dashboard Compatibility" section says the dashboard "pulls the first 5 unchecked `- [ ]` lines (in file order) as next steps." Investigating this project's dashboard card (which was showing stale/paused items ahead of active Phase 4 work), we found the dashboard's actual code takes the *last* 5 unchecked lines, not the first — CLAUDE.md and the implementation have drifted apart.

But fixing the slice direction alone doesn't solve the underlying problem: raw file-order position is a bad proxy for "current work" once a project has paused or future phases interleaved with active ones. In this project, Phase 3 (PAUSED) sits earlier in the file than Phase 4 (the actual active phase) but contains the most recently-touched work (a FreeRouting autorouter session from 2026-08-05/06), while Phase 4's own heading was stale — labeled `*(Not yet started)*` despite being 4/6 complete. Neither "first N" nor "last N" reliably surfaces true current priorities; the ordering needs to be phase-aware, and phase-status labels need to be trustworthy for that to work.

**Suggested change:**

1. Fix the dashboard's parser to derive "next steps" from phase headings rather than raw line position — e.g., skip phases whose heading is marked `PAUSED`/`Future`, and prefer unchecked items from the most-advanced phase with any checked items (a proxy for "currently active").
2. That fix only works if phase-status labels stay accurate. Add a rule (Session End Routine or Work Package Conventions) that the phase heading must be updated the moment the first item in that phase is checked off, so labels like "Not yet started" don't go stale while work is actually happening (as Phase 4 did here).
3. Once the dashboard's actual logic is corrected, update the "Project Dashboard Compatibility" section in CLAUDE.md to describe the corrected (phase-aware) behavior — not just flip "first" to "last," which would just document the current bug instead of fixing it.
